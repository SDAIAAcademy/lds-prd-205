ستخرج من هذا المختبر بـ

  • نسخة أولى من الشارح تعمل على جهازك: الصفحة، والبحث عن الحجز، والقاعدة والرسوم.
  • مستودع Git فيه أربعة إيداعات: البداية، ثم إيداع لكل خطوة تحققت منها.
  • تغيير من الوكيل كسر ما كان يعمل، اكتشفته وتراجعت عنه.

ما تحتاجه

start.zipمجلد البداية: البيانات الاصطناعية، وستة حجوزات للعرض. v1_broken.zipالخطوة 3 بعد «ترتيب» قام به وكيل دون طلب. للخطوة 5. v1_step1.zipالحالة المرجعية للخطوة 1، إن تعطل وكيلك. v1_step2.zipالحالة المرجعية للخطوة 2. v1_step3.zipالحالة المرجعية للخطوة 3.

سياسة الذكاء الاصطناعي: كامل. الوكيل يكتب الشيفرة، وأنت تتحقق وتودع وتتراجع. موجزك وملف سياقك من المختبرين 1.1 و1.2 معك؛ إن لم يكتملا فاطلب المرجعيين من المدرّب.

الخطوات

1 · جهّز المستودع من مجلد البداية مع موجزك وملف سياقك، وأودع 5 دقائق

فك start.zip، وضع فيه BRIEF.md وAGENTS.md، ثم في الطرفية داخل المجلد:

git init
git add .
git commit -m "Start: brief, context file and data"
git log --oneline

2 · الخطوة 1: الصفحة وحقل الرمز؛ شغّل وتحقق وأودع 10 دقائق

الخطوة 1 فقط من الخطة: خادم صغير في app.py بمكتبة Python القياسية يعرض static/index.html على 127.0.0.1:8205. الصفحة عربية ومن اليمين إلى اليسار، فيها حقل «رمز الحجز» بعنوان وزر. لا بحث بعد. ثم أخبرني كيف أشغّله.

شغّل uv run app.py وافتح العنوان. تحقق: العنوان بالعربية، والحقل له عنوان، والصفحة من اليمين. أوقف الخادم بـ Ctrl+C، ثم:

git status
git add .
git commit -m "Step 1: page with the booking-code form"

3 · الخطوة 2: البحث عن الحجز وعرض الأجرة؛ شغّل وتحقق وأودع 10 دقائق

الخطوة 2 فقط: عند إدخال رمز، ابحث عنه في data/bookings.csv واعرض اسم الأجرة من data/fare_rules.json والمسار. رمز غير موجود: رسالة «لم نجد حجزًا بهذا الرمز». لا تغيّر غير ذلك.

جرّب حجزين من الستة ورمزًا غير موجود. نجحت الثلاثة؟ أودع: git commit -am "Step 2: look up the booking and show its fare".

4 · الخطوة 3: القاعدة والرسوم؛ شغّل وتحقق وأودع 10 دقائق

الخطوة 3 فقط: اعرض رمز القاعدة ونصها، وهل يُسمح بالتغيير الآن بحسب الساعات حتى الإقلاع، ورسوم التغيير من القاعدة. الحساب في البرنامج. لا تغيّر غير ذلك.

تحقق بحجزين: واحد يُسمح بتغييره، وواحد لا يُسمح (الساعات أقل من الموعد). أودع.

5 · جرّب تغيير الوكيل المرتب، واكتشفه بالتحقق، وتراجع عنه 10 دقائق

طلب أحدهم من الوكيل «رتّب الشيفرة»، فأعاد كتابة جزء يعمل. انسخ app.py من v1_broken.zip فوق ملفك، ثم:

git diff --stat
uv run app.py

ماذا يحدث؟ لا تطلب من الوكيل أن يصلح ما كسره. عد إلى آخر إيداع يعمل:

git restore .
uv run app.py

اكتب في سطر: ما الذي تغيّر دون طلب، وكيف عرفت.

6 · فكرتك: أول خطوة عاملة وأول إيداع 15 دقيقة

في مستودع فكرتك: اطلب الخطوة الأولى من خطتك وحدها، وشغّلها، وتحقق منها، وأودعها. خطوة صغيرة تعمل خير من ثلاث لا تعمل.

✱ إضافي

اقرأ git diff للتغيير المكسور (قبل التراجع) واكتب في سطرين ما غيّره الوكيل دون أن يُطلب منه.

أسئلة تحقق

  1. كم إيداعًا في git log --oneline؟ وهل كل إيداع يعمل لو عدت إليه؟
  2. في التغيير المكسور: أي تحقق كشفه، وهل كانت الشاشة ستدلك عليه دون تشغيل؟
  3. لماذا تراجعت بدل أن تطلب إصلاحًا فوق التغيير؟
للمدرّب
  • التحقق من الحل: uv run labs/solutions/run_all.py 1.3. ينشئ مستودعًا مؤقتًا، ويودع البداية والخطوات الثلاث بعد تحقق كل منها، ثم ينسخ التغيير المكسور فيفشل التحقق، ويتراجع بـ git restore .. النتيجة: أربعة إيداعات، والتغيير المكسور غيّر ملفًا واحدًا.
  • التغيير المكسور يغيّر اسم عمود المفتاح من ref إلى booking_ref «للوضوح»، والملف ما زال ref: البرنامج ينهار عند التشغيل برسالة KeyError.
  • رسوم الخطوة 3 في الحالة المرجعية هي رسوم القاعدة دون ضرب، والحجوزات الستة كلها لمسافر واحد ورحلة واحدة، فلا يظهر الخطأ هنا. لا تنبّه إليه: يظهر في المختبر 2.1.
  • الخطأ الشائع: git add . قبل التحقق، أو طلب «الخطوات الثلاث معًا». أعد المشارك إلى خطوة واحدة.
  • لم يُشغَّل هذا المختبر على وكيل حقيقي عند إعداد المقرر: الحالات المرجعية تمثّل ردود الوكيل، وفُحصت بالسكربت.
